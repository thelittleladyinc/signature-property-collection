# signaturepropertycollection.com — rebuild

A from-scratch, free-to-host rebuild of signaturepropertycollection.com for
Christine Gwinnup / Signature Property Collection, built for GitHub + Netlify
instead of the old AgentFire/WordPress platform. Generated by `build/build.py`
— a plain Python static-site generator, no Node build step required.

**Branding note:** this project originally used a placeholder "Bold
Collective" name/domain. As of this update it's fully renamed to Signature
Property Collection, matching your real logo, your existing marketing
collateral (Drive docs, articles, guides), and the domain that already
carries your SEO/backlink history — see "The domain decision" below.

## What's in here

```
build/
  build.py            — the site generator (run this to regenerate /site)
  assets/             — source CSS, JS, vendored Leaflet, county GeoJSON
site/                 — GENERATED output — this is what Netlify publishes
netlify.toml          — Netlify build config (runs build.py automatically)
```

Don't hand-edit files in `site/` — they get overwritten every time
`build.py` runs. Edit `build/build.py` (content/copy) or `build/assets/`
(styles, scripts, data) instead.

## Netlify vs. GitHub vs. Render — before you merge

These three aren't actually competing options — they do three different
jobs, and this project already uses two of them together:

- **GitHub** is source control, not hosting. It stores the code/history;
  it doesn't serve the website to visitors. It's not an alternative to
  Netlify or Render — it's what feeds either of them.
- **Netlify** is what this site is already built for. It's a static-site
  host: push to GitHub, Netlify runs `python3 build/build.py` (per
  `netlify.toml`) and publishes `site/`, free, with free SSL, a global
  CDN, and — importantly — **Netlify Forms already wired into every lead
  form on the site** (contact, guides, relocation, valuation, lifestyle
  search). This is the right home for signaturepropertycollection.com.
  Recommended: **use Netlify for this site.**
- **Render** is a different kind of platform — it runs actual backend
  servers, cron jobs, and databases (not just static files). This is what
  `bold-collective-command-center` is built on (per its `render.yaml`),
  because it needs to run a nightly job, call the GA4/GBP/Perplexity APIs,
  and persist state. Render is not a replacement for Netlify here; it's
  where a *future* automation backend for this site would live if you
  build one (see "Auto-updating the blog" below).

So: keep this site on Netlify. If/when you wire up automated blog
generation or live analytics, that backend piece can live on Render
(or Netlify Functions, for lighter-weight jobs) alongside it — they're
complementary, not either/or.

build-time-only (a static generator, no live CMS/database), which is a
*feature* for speed/security/cost, not a limitation to work around:

1. **Demand signal.** A scheduled job (this is the Render/cron piece)
   pulls what people are searching using GSC's query data (#4 above) and/or
   a demand-research API like Perplexity (`PERPLEXITY_API_KEY`, already in
   your env vars) — the same `optimization-loop.js` /
   `perplexity-demand.js` pattern documented in
   `market-takeover-template/docs/COMMAND-CENTER-WIRING.md`.
2. **Draft.** For a promising, under-covered query (e.g., "best school
   districts near Windsor CO" or "how much is a well permit in Larimer
   County"), the job drafts a new blog post or guide — the same shape as
   the entries already in `build/data/blog.json` (`slug`, `title`, `date`,
   `meta`, `paragraphs`).
3. **Commit.** The job appends the new entry to `build/data/blog.json` (or
   `MARKET_TOPIC_PAGES` for an evergreen guide) and pushes that change to
   this GitHub repo — either directly via the GitHub API, or by opening a
   PR for you to approve first (recommended at the start, so you're
   reviewing AI-drafted copy before it goes live — you can always turn on
   auto-merge later once you trust the output).
4. **Publish.** Netlify already auto-deploys on every push to `main` — no
   new deploy step needed. A commit lands, the site rebuilds, the new post
   is live, typically within a minute or two.

None of this needs a new hosting platform or a rewrite of this site — it's
one new small service (on Render, or even a scheduled GitHub Action) that
writes into `build/data/blog.json` and pushes. I'd suggest starting with
step 1-2 read-only (a weekly digest of "here's what people are searching
that you don't have a page for yet") before wiring up auto-commit, so you
can sanity-check the topic suggestions before any auto-drafting begins.

## Deploying (and how to give Claude push access)

Claude never has — and can't be given — your GitHub password, so it can't
log in and push the normal way. There's no credential-typing path around
that. Two real options:

1. **Simplest: you push it yourself.** Create a new empty GitHub repo (e.g.
   `signature-property-collection`), then from a terminal with this folder:
   ```
   git remote add origin https://github.com/<you>/signature-property-collection.git
   git push -u origin main
   ```
   Then in Netlify: **Add new site → Import from Git → pick the repo.**
   Netlify reads `netlify.toml` automatically.
2. **Claude pushes it for you, using your Mac's own git credentials.** If
   you create the empty GitHub repo yourself (via your already-logged-in
   browser — just clicking "New repository," no password typed by Claude)
   and give Claude the repo URL, Claude can write these files onto your Mac
   and run `git push` *from your Mac's terminal*, which uses whatever
   git/GitHub auth is already set up there (SSH key or saved credential) —
   Claude still never sees or enters a password. Ask for this if you'd
   rather not touch the terminal yourself.

Once it's on GitHub and imported into Netlify, add
`signaturepropertycollection.com` as a custom domain in Netlify's domain
settings and follow their DNS instructions — see "The domain decision" above
for why this needs to be a deliberate, careful cutover rather than a quick
DNS flip, since that domain is your live WordPress site today with real
organic traffic on it.
