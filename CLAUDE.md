## Fair housing / neighborhood copy

Do not write housing marketing that expresses a preference for protected classes or family status.

Avoid promotional phrases such as “family-friendly,” “great place to raise a family,” “safe and nurturing,” or describing who “typically moves here” by age, family composition, religion, race, ethnicity, disability, or other protected traits.

Objective information may be presented neutrally when it is accurate and relevant. For schools, name the district or objective program information and encourage buyers with specific needs to confirm current offerings directly. Do not characterize schools as “excellent,” “best,” or otherwise steer buyers based on school reputation.

The multigenerational funnel must ask about **property features** (entrance, bedroom/bath placement, kitchen, ADU/guest house, walkout, land, etc.), not protected-class characteristics or who will live there.

**Form submissions Netlify marked as spam (2026-11-03; `tests/test-form-spam.js`).** Netlify keeps a submission it judges spam (the hidden spam field filled, or its own filter) in each form's Spam tab and never hands it to `submission-created.js`, so a real person whose browser auto-filled the hidden field was lost without a trace. `form-spam-count.js` (scheduled every 6 hours, netlify.toml) counts them for the last 7 days with `lib/_form-spam.js` (shared byte for byte): Netlify's REST API with `NETLIFY_FORMS_TOKEN`, else the `BLOBS_TOKEN` both sites already hold (Authorization header only, redirects refused), `GET /sites/{id}/forms`, then `GET /forms/{id}/submissions?state=spam` per form; for any form with an answer the verified list is read too, and one id in both refuses the count (Netlify not keeping spam apart would otherwise call real leads spam). Counts only (form name, how many, the newest time; never a name, email, phone or message), saved in Blobs (`form-spam-count-<site id>.json`) and shown on /status as the optional row "Form submissions Netlify marked as spam" (never the site failing; a failed or partial read says "Could not count", never zero; a count over 13 hours old is not green), with the link to the site's Netlify forms page. Nothing is sent or written to Lofty. **Never a bare 500 (2026-11-04):** the thelittleladysellshomes copy answered HTTP 500 on every scheduled run from Nov 3 because the Blobs store could not be opened after the count (`getStore()` threw: its functions get no `BLOBS_SITE_ID` + `BLOBS_TOKEN`, and a Lambda-style scheduled function has no Blobs context without `connectLambda(event)`). `runSpamCount` in `lib/_form-spam.js` now opens the store from those settings, else this site's own store through the context Netlify sends with the run; the count and the save fail on their own, and every run answers JSON (`complete`, `saved`, `problem`, error names only): 200 only when the count is complete and saved, else 503.
